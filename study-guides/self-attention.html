Self-Attention

Self-attention lets each token collect information from the other tokens in the sequence. Each token asks a query, compares it with every token's key, and takes a weighted mix of their values.

One token, one attention step

Sentence: “the river bank was muddy”. We follow the token bank. Is it a money bank or a river bank? Attention decides. The numbers are a toy example with dk = 4, computed live on this page.

Understand

The idea in six steps

  1. The model turns each token into a vector, the embedding x. At the start, “bank” has the same vector in every sentence.
  2. The model multiplies each x by three learned matrices. This gives three vectors per token: a query q = x·W_Q (“what I am looking for”), a key k = x·W_K (“what I contain”) and a value v = x·W_V (“what I give if you pick me”).
  3. For one token, the model takes the dot product of its query with every key. A large dot product means a good match. This number is the score.
  4. The model divides each score by √d_k. Without this, scores grow with the vector size, softmax gives almost all weight to one token, and the gradients become very small.
  5. In a GPT-style model, a token may not look at later tokens. The causal mask sets their scores to −∞. Then softmax turns the scores into weights that are 0 or more and add up to 1.
  6. The output for the token is the weighted sum of the values. The block adds this output to the token's vector (the residual connection). Now “bank” carries information about “river”.

Analogy: a library search. The query is what you type. The keys are the book titles. The values are the books' contents. You don't get one book. You get a blend of all the books, mixed by how well each title matched. The analogy stops at learning: in attention, the model learns what to type, how to title the books and what to put in them.

Code · PyTorch

One head of causal self-attention

This is the same structure as the Head class in Karpathy's “Let's build GPT”. Each line maps to one step above.

import torch, torch.nn as nn, torch.nn.functional as F

class Head(nn.Module):
    """One head of causal self-attention."""
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.query = nn.Linear(n_embd, head_size, bias=False)  # W_Q
        self.key   = nn.Linear(n_embd, head_size, bias=False)  # W_K
        self.value = nn.Linear(n_embd, head_size, bias=False)  # W_V
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):                                   # x: (B, T, C)
        B, T, C = x.shape
        q = self.query(x)                                   # (B, T, hs)  step 2
        k = self.key(x)                                     # (B, T, hs)
        wei = q @ k.transpose(-2, -1) * k.size(-1) ** -0.5  # (B, T, T)   steps 3-4
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float("-inf"))  # step 5: mask
        wei = F.softmax(wei, dim=-1)                        # each row sums to 1
        v = self.value(x)                                   # (B, T, hs)
        return wei @ v                                      # (B, T, hs)  step 6

Remember

Key facts and common mistakes

Key facts

  • In self-attention, Q, K and V all come from the same sequence. In cross-attention, Q comes from one sequence and K, V from another.
  • Attention has no sense of order by itself. Position comes from positional embeddings (or RoPE) added before or inside attention.
  • Multi-head attention runs several heads in parallel with smaller head size, then joins their outputs and projects them with W_O.
  • Compute and memory for the scores grow as T². Doubling the context gives 4× the score matrix.
  • At inference, the model caches K and V of past tokens (the KV cache). Each new token computes only its own q, k and v.

Common mistakes

  • Softmax over the wrong axis. Each row (one query) must add up to 1: dim=-1.
  • Masking with 0 instead of −∞. A score of 0 still gets weight after softmax.
  • Dividing by dk instead of √dk.
  • Thinking the output replaces the token's vector. The residual connection adds it.
  • Reading weights as “explanations”. High weight shows where information flowed in one head, not why the model decided.
